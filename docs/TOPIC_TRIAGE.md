## 0. TL;DR

原文档的方向排序是按「3–5 人小组 + 2–4 张 A100 + LLM 预算」写的。换上我们的约束后排序**基本反转**：
它排第 1、第 3 的两个方向（GPU 一阶方法、LLM×OR）对我们几乎整条关闭，
而它排第 4（ML 增强精确求解器）和第 2（DFL）里那些**计分单位与硬件无关**的子课题变成最优解。

**只做一件事的话，做这个**：把本仓库已有的 Lagrangian-cut 基线往「**学习摊销割生成**」推
（原文档 Topic 4.3 + 4.1 的合流，也正是 `HANDOFF.md` 第 7 节 A3 的方向）。
理由见 §3.1——核心是：**论文定理 3 白送给我们一个「学习组件不可能损害界」的安全性定理**，
而这恰好是方向四整条线最想要、最难拿到的东西。

## 1. 三条约束如何改变筛选标准

### 约束一：无 GPU → 只选「记账单位与硬件无关」的课题

这是最容易被误判的一条。**无 GPU 不等于「算法加速类课题」全部关闭**，
因为算法研究的记账单位有两种：

| 记账单位 | 是否吃硬件 | 例子 |
|---|---|---|
| wall-clock 秒数 | **吃**，无 GPU 直接出局 | 「cuPDLP 比 Gurobi 快 3 倍」 |
| oracle 调用数 / 迭代数 / 样本数 / 节点数 | **不吃**，硬件无关 | 「受限分离把 oracle 调用从 2019 降到 800」 |

我们仓库现有的复现结果（`README.md` 那张表）恰好就是第二类——`oracle (MIP) calls` 这一列
换任何机器都成立。**凡是主定理和主实验图能用第二类单位表述的课题，无 GPU 不吃亏。**

反过来，凡是卖点必须是 wall-clock 的（GPU 批量核、百万列端到端提速、基础模型秒级响应），
一律出局，不要自欺。

### 约束二：无 LLM API 经费 → 方向二整条关闭

原文档方向二（Topic 2.1–2.4）全部需要 LLM 推理或微调。
本地跑开源模型同样需要 GPU，所以**没有绕过去的办法**。

唯一可回收的碎片见 §4.2（Topic 2.1 的「验证器」那一半是纯整数规划，不需要 LLM）。

### 约束三：执行者是 AI agent → 这是最被低估的约束

Agent 的能力画像很不对称：

| Agent 强 | Agent 弱 |
|---|---|
| 高吞吐地实现算法、跑参数扫描、做消融 | 无验证信号的长链条证明（会写出「看起来对」的假证明） |
| 构造仿真器、基准、数据管线 | 判断一个想法是否已被发表 |
| 数值反例搜索、可证伪实验 | 在没有判据时决定何时放弃 |

所以选题的隐含准则是：**优先选「做错了会立刻被实验打脸」的课题。**

我们自己就有活样本：`HANDOFF.md` §6 里 adaptiveA 的失败，是被 `delta=0` 真收敛实验
干净地判死的——这种「判据清晰、负结果也是结论」的课题，才是 agent 能安全推进的。
而纯理论课题（无数值验证回路）交给 agent 的风险最高，处理办法见 §4.4。

**推论**：优先选「负结果也算有效结论」的课题。我们没有资源赌一个必须成功的方向。

## 3. 强推荐四项 + 首个实验规格

### 3.1 【第一顺位】学习摊销 Lagrangian 割生成（Topic 4.3 + 4.1 合流）

**接口**：本仓库 `claude/paper-reproduction-method-extension-orc8dx` 分支，
`HANDOFF.md` §7 的 A3。

**为什么排第一（四条理由，按重要性）**

1. **定理 3 白送一个安全性定理。**
   论文定理 3 保证：在 `delta=0` 下，*任何* 第一阶段割方法（即任何 Π_s 选择策略）
   都收敛到同一个 z_D。翻译成机器学习的语言就是：
   > 把选基器换成一个神经网络，哪怕它学坏了，**也不可能损害下界的正确性和最终质量，
   > 最差只是变慢。**

   而原文档 Topic 4.1 整篇的目标就是「可证明不劣化的学习策略」——那是求解器厂商
   不敢部署 ML 的**唯一核心顾虑**。在一般 B&B 里这个性质要费很大劲去构造（在线切换、
   竞争比）；**在我们这个设定里它是免费的**。这是审稿人会买账的卖点，
   也是一篇论文最值钱的那句话。

2. **计分单位是 oracle 调用数，硬件无关。**（§1 约束一）无 GPU 完全不吃亏，
   而且我们已经有了 baseline 数字（rstr2/rstrmip 800 次 vs exact 2019 次）。

3. **边际成本最低。** 复现已定稿可信，实例生成器、五种割生成法、验证测试、
   收敛判据全在。新增的只是一个特征提取器 + 一个小模型。

4. **文献口子是开的。** 「把已生成的割当训练数据、未求解的场景当测试」
   在 Lagrangian-cut 文献里被点名为 open direction，
   而目前公开工作仍停留在 SVM 分类 Benders 割（IJOO 2019）这一层。
   *（投稿前核实原文措辞与最新 arXiv。）*

**目标期刊**：IJOC（首选，重实现与可复现性）；若安全性定理讲得漂亮可冲 OR。

**给 agent 的首个任务——注意：第一步是 profiling，不是训练**

这一步不能跳。整个课题的立论是「摊销掉贵的那部分」，
所以必须先用数据回答「贵的到底是哪部分」：

```
任务 P0（profiling，预计 1–2 天）
  在 SSLP (m=10,n=25,S=30) 与 decoupled 强坍缩实例上，method=rstrmip，delta=0，
  分别统计每轮耗时构成：
    (a) oracle MIP Q*_s(π,π0) 求解          ← 预期占大头
    (b) 式(28) 选基 MIP                      ← 若这里也占 20%+，则学习选基器本身就有价值
    (c) 主问题 LP 与其它
  输出：一张堆叠柱状图 + 一张表，写入 docs/。
成功判据：无（这是测量，不是实验）。但 (a)(b) 的比例决定下一步做哪个分支。
```

```
任务 P1（按 P0 结果二选一）
  分支 A —— 若 (b) 占比可观：监督模仿 rstrmip 的选基器
    输入特征：当前 (x̂, θ̂)；候选池中每条 π^k 的 ⟨π^k, x̂⟩、历史违反量、age、范数、
              与已选方向的夹角
    标签：式(28) MIP 实际选中的 K 个方向
    模型：LightGBM 或 2 层 MLP（CPU 秒级训练，禁止用大模型）
    训练/测试：同一 SSLP 实例族随机抽 80/20，**测试实例必须是训练时没见过的**

  分支 B —— 若 (a) 压倒性占大头（更可能）：摊销 oracle 本身
    目标不是替换选基器，而是**预测 oracle MIP 的好起点**：
    用 (π, π0) 与场景参数预测 Q*_s 的最优 y（或其整数部分），作为 MIP 的 warm-start /
    变量定序。学错了只是 warm-start 差，**解出来的仍是精确 Q*_s，不影响割的有效性**。
    → 这个「学习不改变正确性、只改变速度」的结构，是本课题第二个免费的安全性论证。

评价协议（两个分支通用，不许偷懒）：
  delta=0，跑到 stop_reason=no_cut 为止
  指标 1：到达 z_D 的 oracle 调用数
  指标 2：到达 z_D 的总 wall-clock（作为辅助，不作为主张）
  指标 3：选基/预测本身的开销占比
基线：rstrmip（论文最好的方法）、rstr2、exact
成功判据：在 held-out 实例上，oracle 调用数 ≤ rstrmip 的 0.9 倍（分支 B），
          或选基总开销降 ≥50% 且 oracle 调用数 ≤ rstrmip 的 1.1 倍（分支 A）
失败判据：达不到上述，且在 3 组不同实例族上稳定达不到
失败后的动作：**不要调参硬救。** 记录为负结果，转 §3.4（非精确 Benders / ε-割），
          那条路复用同一套代码。
```

**已知风险**
- 训练实例分布太窄 → 学到的是「这个生成器的指纹」而非可迁移规律。
  对策：测试集必须跨 `(m,n,S)` 规模与 `capacity_scale` / `decoupled` 旋钮。
- HiGHS 下 `delta=0` 撞时间墙（`HANDOFF.md` §6 已踩过这个坑）。
  对策：**先做 Gurobi 后端**（`HANDOFF.md` §8 TODO-1），这仍然是第一件基础设施。
  学术 license 免费、CPU 版即可，不需要 GPU。

### 3.2 【第二顺位】整数下游 DFL 的梯度估计统一分析（Topic 3.3）

**为什么**：`PyEPO`（PyTorch 端到端 predict-then-optimize 库，支持 LP 与 IP）现成，
实例都是小规模背包/最短路/匹配，CPU 完全够；
所有 claim 都是统计性的、可证伪的；**而且负结果本身可发表**——
「整数下游时 DFL 在什么条件下不优于两阶段」是社区真正想知道的问题。

**关键设计**：不要一上来做理论。先做一件 agent 最擅长、而人类研究者嫌烦的事：
**把「真梯度」测出来。**

```
任务 Q0（实证核心，也是论文第一张图）
  取 4 类小规模下游问题：0-1 背包、最短路、二分匹配、单机加权延误调度
  （规模控制在可以精确/枚举计算期望决策损失次梯度的范围内）
  对 5 类梯度估计量做同条件对比：
    SPO+ / 黑箱微分(DBB) / 扰动优化(Fenchel–Young) / score function / LP松弛+隐式微分
  固定同一预测模型、同一数据生成过程、同一随机种子集
  用大量 Monte Carlo 抽样得到「真梯度」参考值
  测每个估计量的 bias 与 variance，随扰动温度 / 采样数 / 问题规模的曲线
  产出：bias–variance 前沿图（每类问题一张）
成功判据：能识别出至少一个「被支配区域」——即存在某个估计量在整个参数范围内
          被另一个同时在 bias 和 variance 上压制。这就是论文的第一个 finding。
```

理论部分（第二阶段）只需解释你已经测到的曲线，而不是凭空猜测——
**这是把 agent 的证明风险降到最低的做法：先有现象，再有定理。**

**目标期刊**：IJOC / OR；前置可投 NeurIPS/ICML。

### 3.3 【第三顺位】约束中含预测参数 + 决策导向共形校准（Topic 3.4）

**为什么**：共形预测的有限样本保证走的是**可交换性**这条极其标准的论证路线，
模板化程度高、agent 写错的概率低；实验规模小；
「可行性违反率」是一个可以精确测量、无法含糊其辞的量。
是四个推荐里**理论风险最低**的一个。

```
任务 R0
  问题：带容量约束的分配 / 多产品报童，预测参数进约束（需求下限、容量）
  对比四种方案：
    (a) 两阶段 + 分位数回归
    (b) 机会约束 + 高斯假设
    (c) split conformal 校准半径（固定 α）
    (d) 决策导向校准：把 α 本身当作可学参数，用验证集上的真实决策成本来选
  测：样本外可行率 vs 样本外成本，画成曲线（不要只报单点）
成功判据：(d) 在同等可行率下成本低 ≥3%，或同等成本下可行率高 ≥3 个百分点，
          且在 3 组不同噪声水平下稳定成立
失败判据：(d) 与 (c) 在曲线上重合 → 说明「校准水平」这个自由度不含决策信息，
          记录为负结果并转向「recourse 成本端到端建模」这个子问题
```

**目标期刊**：OR / M&SOM（若落到库存/物流）。

### 3.4 【第四顺位 / §3.1 的备胎】非精确 Benders 与割有效性证书（Topic 1.2-CPU + 6.2）

**为什么放这里**：它和 §3.1 共用本仓库的同一套 Benders/Lagrangian 骨架，
所以当 §3.1 的判据失败时，**切换成本接近零**——这正是我们需要的备胎结构。

去掉 GPU 后剩下的、仍然成立的核心问题是：
> 当子问题只被近似求解时，用近似对偶解构造的割**可能切掉最优解**。
> 如何构造可证明有效的 ε-割，并给出非精确下的收敛性？

这是一个**引理级别、CPU 可完全验证**的目标：
有效性可以用「对已知最优解检验割是否切掉它」直接数值证伪，
agent 有清晰的验证回路。原文档给的 Plan B（「聚焦理论投 MP」）在无 GPU 下反而成了 Plan A。

配合 `HANDOFF.md` §7 的 B1（析取割突破 z_D 天花板）可以组成一篇更完整的文章。

## 4. 需要特别说明的四件事

### 4.1 「研究 GPU 调度」不需要 GPU（Topic 7.2）

这条容易被自己的约束吓退。Topic 7.2（GPU 集群资源分配、MoE 专家–设备映射）
本质是**带通信成本的分配/划分问题**：整数规划建模 + 近似算法 + 在线版本 + 仿真验证。
建模和仿真全是 CPU 活。真正的门槛是拿到真实的作业 trace，而不是拿到 GPU。

相对 Topic 7.1，这条赛道的 OR 侧论文明显更少。列为 ✅ 备选。

### 4.2 方向二唯一可回收的碎片：Topic 2.1 的「验证器」那一半

Topic 2.1 是「LLM 生成割 + 自动证明有效性」。其中**证明器那一半完全不需要 LLM**：

- (a) LP 蕴含检验（Farkas 对偶证书，判断候选不等式是否已被 LP 松弛蕴含）
- (b) CG 秩 1 的构造性证明（解一个 MIP 找乘子 u 使 ⌊uA⌋x ≤ ⌊ub⌋ 恰为该不等式）

这是纯整数规划工作，CPU 可做。把生成器从 LLM 换成枚举式/进化式生成器，
就变成「**有效不等式的自动发现与认证系统**」。

**但要诚实**：抽掉 LLM 之后，它与经典割生成文献的区分度显著下降，
novelty 论证会比 §3.1–3.3 吃力得多。列为「有余力再说」，不建议作为主线。

### 4.3 Topic 7.1 的窗口正在关闭——原文档这一条已经过时

原文档把「优化 × AI 系统」称为「最值得投入的新兴蓝海」，并说「OR 顶刊上的系统性建模仍少」。
截至 2026-09 检索，**这个判断已经不成立**：
「KV cache 内存约束下的稳定域刻画」这个头条已经被多篇 2026 年工作占住
（arXiv:2605.04595 的排队论稳定性框架、arXiv:2604.11001 的可证明稳定调度、
arXiv:2602.02987 的 prefill–decode 争用与渐近最优控制，
还有一篇专门的 position paper arXiv:2605.01280）。

好消息是它**确实不需要 GPU**（BurstGPT、Azure LLM inference trace、Mooncake trace 都是公开的，
配一个离散事件仿真器就够）。所以如果一定要做，**必须收窄到还没被占的口子**，
例如：给定稳定域之后的 SLO 约束下成本最优容量规划，或 agentic / 多轮工具调用型 workload
（这类 trace 是 2026 年才出现的）。

不建议作为主线——我们没有资源去抢一个正在被多个组同时冲的头条。

### 4.4 纯理论课题为什么对 agent 危险，以及怎么救

Topic 3.1（DFL×DRO）、6.1（新歧义集）、6.3（双层桥梁）、5.1（NCO 近似比）、4.2（伪维数界）
的共同点是：**零算力需求（对我们友好）+ 零数值验证回路（对 agent 致命）**。
Agent 在没有反馈信号时会产出「结构完整、引用齐全、但某一步是错的」的证明，
而这种错误在人工精读之前不会暴露。

**如果一定要做其中之一，强制加一道工序**：
> 在写证明之前，先让 agent 写一个**数值反例搜索器**——
> 随机生成小实例，暴力验证待证命题是否成立。
> Agent 的第一项任务是**试图证伪自己的猜想**，而不是证明它。
> 只有搜索器在数千个随机实例上找不到反例，才允许进入证明阶段。

这条工序把「无验证回路」变成「有验证回路」，是让理论课题变得 agent-safe 的唯一办法。

## 5. 交给 agent 的工作规程

前 4 条是从 `HANDOFF.md` §6 的踩坑经验提炼的，后 4 条是通用的。

1. **任何关于「界」的结论，必须确认 `stop_reason = no_cut`。**
   `time_limit` 的数值不是收敛值，不可用于任何比较。
   （`HANDOFF.md` §6 记录过一次因此得出错误结论的经历。）
2. **每个实验必须在跑之前写下成功判据和失败判据**，并在结果里逐条对照。
3. **负结果必须完整记录，不许悄悄换题。**
   adaptiveA 的失败结论（violation-targeted 完胜 variance-targeted）
   比它成功了还有价值。
4. **profiling 先于优化**：任何「加速某部分」的课题，第一步都是测量那部分到底占多少。
5. **每个 claim 必须附带一个「能推翻它的实验」**，并说明为什么该实验没能推翻它。
6. **文献查重**：每个自认为「新」的想法，动手前先检索近 24 个月的 arXiv 与目标期刊，
   把检索词与结果记进实验日志。§4.3 就是这一条的价值示范。
7. **基线必须用官方实现与默认参数**，并报告硬件与求解器版本
   （IJOC/MPC 会实际测试代码）。
8. **不许引入大模型 / GPU 依赖**。特征工程 + LightGBM/小 MLP 是上限。
   一旦某个方案需要 GPU 才能验证，说明选题跑偏了，回到本文档重选。
